# fsql / tree-fucker layer investigation

This file records the original investigation, which used a temporary probe. Artifact paths below are relative to the fsql repository root and name historical outputs that the repository probes do not need.

- The fsql source was commit `f6da063a1ceee38164576398ada9dca1c5b6f77f`.
- The measured tree-fucker was c6c16eb07a7c1e00b45c9f9e1c01321afb347329, as pinned by fsql.
- The inspected local tree-fucker was b0a863b20b7b0ab76119752a4b3f0d2e39e97e0f. The commits between the two change portability, error mapping, and CI and leave the hot path as it was.
- The probe's Cargo.lock started as a copy of the fsql Cargo.lock and kept its dependency versions.
- The executables were `target/release/fsql-layer-probe` and `target/release/alloc`, and the CLI was `target/release/fsql`.
- The fixture lived in a temporary directory on tmpfs. `benchmarks.run.fixture(root, 20000)` generated it, and it had 20035 descendants.
- Timings were warm-cache with two warmups and 25 measured iterations per layer. The variants ran sequentially without statistical randomization. The probe prepared the SQL once. No perf, strace, or allocation counters ran during final timings.
- CLI verification used two warmups and 15 measured subprocess invocations with output to /dev/null. The median was 40.918 ms.
- The probe installed the Scan governor with foreground duty 1.0, as fsql does. Default Scan has no anchors. The anchored variant used a budget of 100000, and the fixture fit within it.
- Count modes avoid collecting full paths. Every path mode collects paths through the same existing traversal benchmark helpers. Do not treat count and path modes as identical operations.
- The probe required expected result counts. It also compared the existing and direct JSON serializer outputs as full path multisets, including special filenames.
- query-direct is a specialized experiment for one text path column. It cannot replace the general writers for other output types.
- The allocation instrument is separate, and its counts include realloc calls. Requested bytes are cumulative allocation traffic and differ from peak resident memory.
- strace counts for a single CLI path query were 20035 writes, 166 getdents64 calls, and 85 statx calls. The size query's counts are in the tool transcript.
- The std and Scan syscall probe ran two warmups plus one measured iteration, so dividing the directory syscall counts by three gives 66 for std and 166 for Scan per traversal.

## Reproducing measurements

Use [the repository layer probes](../layers.md) for new measurements. They include query preparation in each iteration, use an anchor budget of 1024, validate complete path multisets, and report stats_alloc counters with reallocations separate. Their generated fixture has a different shape, so the numbers above are not directly interchangeable baselines for the new harness.
